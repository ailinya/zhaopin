# 2026-11-19 工作日志

## 修复：后端 uv run 启动失败（hatchling readme 路径错误）

- 现象：`uv run uvicorn app.main:app ...` 报 `ValueError: Readme path must be within the project directory: ../README.md`，发生在 hatchling 构建 editable 包阶段。
- 根因：`backend/pyproject.toml` 中 `readme = "../README.md"` 指向 backend 目录之外，hatchling 不允许 readme 路径越过项目目录。
- 修复：删除 `readme = "../README.md"` 这一行（非必需字段，不影响运行）。根目录 README.md 保留不变。
- 验证：`uv run python -c "print('build ok')"` 成功，构建阶段已正常通过。
- 附注：验证时曾因默认 30s 超时导致 llvmlite/torch 等大包下载失败，改用清华镜像 `UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` 并加大 `UV_HTTP_TIMEOUT=180` 后成功；这是网络问题，与代码无关。

## 修复：/api/candidates 报 sqlite3.DatabaseError: database disk image is malformed

- 现象：GET /api/candidates?page_size=100 返回 500，SQLAlchemy 查询 candidates 时报 `database disk image is malformed`。
- 诊断：`backend/interview.db`（主库）本身完全健康，`PRAGMA integrity_check=ok`；损坏的是 `interview.db-wal`（约 4MB）。逐帧校验发现 WAL header checksum 与所有帧 checksum 均失配（WAL 从 7 月至今未 checkpoint，缓存了大量写入）。主库与各表数据完整（candidates 4 / users 1 / positions 4 / interviews 3 / audit_logs 188），WAL 中无主库缺失的数据。
- 修复步骤：
  1. 先备份 `interview.db` + `-wal` + `-shm` 到 `backend/db_backup_20261119_143926/`（已完成，勿删）。
  2. 停止持有该 WAL 连接的后端进程（当时 PID 5616 及其子进程），否则 Windows 下文件被锁定。
  3. 删除损坏的 `interview.db-wal` 与 `interview.db-shm`，SQLite 会在下次连接时自动重建干净 WAL。
  4. 重启后端：`cd backend && uv run uvicorn app.main:app --host 0.0.0.0 --port 8000`。
- 验证：登录 admin/123456 取 token 后带 `Authorization: Bearer <token>` 请求该接口，HTTP 200、`code:0`、返回 4 条候选人数据，端到端通过。
- 防范：`--reload` 模式下进程被 kill/异常退出（如本次为排错手动 Stop-Process）易导致 WAL 未正常 checkpoint 而损坏；正常关闭服务（Ctrl+C）可让 SQLite 完成 checkpoint。若再现此错，先确认主库 integrity_check 是否 ok——若 ok，直接删 WAL/SHM 即可无损恢复；不要随意删主库。
